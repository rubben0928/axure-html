案件資料 Excel 匯入功能 – 系統開發需求說明

一、整體流程與畫面切換 (User Flow)

系統包含三個主要畫面區塊（Page），透過 JavaScript 控制顯示/隱藏 (display: none / block)：

  1. 上傳頁面 (uploadPage)：預設顯示。
  2. 資料檢核頁面 (dataPage)：點擊「開始匯入檢核」後顯示，隱藏上傳頁面。
  3. 匯入完成頁面 (finishPage)：點擊「確認匯入」且檢核全部通過後顯示，隱藏資料檢核頁面。

二、畫面元件細部規格 (UI Component Spec)

1. 上傳頁面 (uploadPage)

元件規格說明行為 / 事件
下載 Excel 範本 Button 按鈕 點擊後直接下載 案件資料匯入範本.xlsx。
開發備註 檔案標頭須包含：計畫年度,計畫編號,計畫名稱,工程核定日期,核定文號,核定經費(千元),工程編號,工程名稱,承辦人,電子郵件。並提供一列正確格式的範例資料。
選擇檔案 <input type="file"> 只限 .xlsx。
開始匯入檢核 Button (主要按鈕) 此階段應先讀取檔案內容。

2. 資料檢核頁面 (dataPage) —— 核心頁面

此頁面需包含以下子元件：

A. 統計摘要卡 (Summary Cards)

  • 總筆數：顯示 currentData.length。
  • 正確筆數：filter(該筆所有欄位無錯誤).length。
  • 待修正筆數：filter(該筆有任何一個欄位錯誤).length。
  • 開發備註 數據變動時（如重新檢核）需即時更新數字。

B. 動態訊息列 (Message Bar)

  • 有錯誤時：紅底／左側紅框，顯示 ⚠ 尚有 N 筆資料需要修正，請處理紅色欄位。
  • 全部正確時：綠底／左側綠框，顯示 ✔ 所有資料檢核通過，可以進行匯入！

C. 資料表格 (Data Table)

  • 欄位：依序顯示「計畫年度、計畫編號、計畫名稱、工程核定日期、核定文號、核定經費(千元)、工程編號、工程名稱、承辦人、電子郵件、狀態」共 11 欄。
  • 輸入模式：所有欄位（除「狀態」外）皆須為 可編輯的輸入框 (<input>)，方便使用者直接點擊修改。
  • 資料綁定：輸入框的 value 需綁定 currentData 物件的對應欄位。當使用者修改輸入框內容時，需即時更新 currentData 物件（監聽 input 事件）。
  • 錯誤樣式 (關鍵)：
    • 當該欄位檢核失敗时，<input> 須加上 CSS 類別 error (紅字 + 紅框)。
    • 欄位下方須顯示具體的紅色錯誤提示文字（如「不可空白」、「格式應為 YYY/MM/DD」）。
    • 正確欄位則維持普通樣式，且錯誤訊息區塊留白或隱藏。
  • 狀態欄 (Status)：顯示徽章 (Badge)。
    • 該筆記錄全部欄位正確：顯示綠色 ✔ OK。
    • 該筆記錄任一欄位錯誤：顯示紅色 ✘ 錯誤。

D. 操作按鈕 (Action Buttons)

  • 「重新檢核」按鈕：點擊後，系統讀取表格中所有 <input> 的最新值，同步回 currentData，再次執行「資料檢核函式」，並重新渲染表格與統計數據。
  • 「確認匯入」按鈕：
    • 預設狀態：disabled (灰色不可點擊)。
    • 啟用條件：當「重新檢核」後，系統判定 待修正筆數 === 0 時，改為 enabled (綠色可點擊)。
    • 點擊行為：觸發「確認匯入」流程（顯示 Modal 二次確認對話框，或直接跳轉至完成頁面）。

3. 匯入完成頁面 (finishPage)

顯示成功圖示與訊息「案件資料已成功匯入系統，共 N 筆。」，並提供「回到首頁」按鈕（重新整理頁面）。

2. 匯入前二次確認 (Important)

⚠️ 強烈建議： 雖然雛型直接跳轉，但基於原始需求文件第 5 點「正式匯入前應由使用者再次確認」，請開發人員在點擊「確認匯入」時，補上 window.confirm('確認要將 N 筆案件資料匯入系統嗎？')，按下「確定」後才執行寫入資料庫動作並跳轉完成頁面。

四、例外處理與邊界條件 (Edge Cases)

🔹 無資料若上傳的 Excel 僅有標頭列無資料，或檔案空白，匯入檢核時應顯示「無資料可匯入，請檢查檔案。」的警示訊息，不切換至資料頁面。
