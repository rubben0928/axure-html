兒童遊戲場資料匯入檔製作教學

本手冊說明如何製作四份匯入用的 Excel 檔案與附件資料夾：備查、維護管理、自主檢查、稽查管理。
適用對象為負責整理與填寫資料的承辦人員。

目錄

  6. 檔案四：稽查管理

一、總覽：你要準備什麼

四個模組各自獨立，請為每個模組準備「一份 Excel」＋「一個放實體附件的資料夾」。

📥 先下載空白範本

四份範本檔放在本教學同層的 匯入範本 資料夾，請下載後直接覆蓋第 2 列起的範例資料填寫（標題列請勿更動）：

  • 1_備查_匯入範本.xlsx備查（含 A、B 兩區範例）
  • 2_維護管理_匯入範本.xlsx維護管理（含合格／待改善／已完成改善範例）
  • 3_自主檢查_匯入範本.xlsx自主檢查（含需上傳／免上傳範例）
  • 4_稽查管理_匯入範本.xlsx稽查管理（含合格／改善中範例）

範本中「公園編碼」與「日期」欄已設為文字格式，避免 Excel 自動移除前導 0 或誤判民國日期，請保持文字格式填寫。

每個模組各交付兩樣東西

  • Excel主資料：每一列是一筆紀錄，欄位內容請依後面各章的對照表填寫。
  • 附件資料夾把該模組要用到的實體檔案（PDF、圖片等）全部集中放在同一個資料夾；Excel 內只要填「檔名」，系統會自動到資料夾裡找對應的檔。

匯入順序很重要

因為「維護管理」要接在「備查」的報告之後，請務必依下列順序準備與匯入：

① 備查→ ② 維護管理→ ③ 自主檢查→ ④ 稽查管理
為什麼？ 維護（定檢）紀錄是「掛在備查的檢驗報告上」的。若備查還沒匯入，維護就找不到可以對應的報告。自主檢查與稽查彼此獨立，順序不拘，但建議一起放在備查、維護之後。

二、通用規則（四份檔案共通）

項目填寫規則
公園統一編碼固定 7 碼數字，不足前面補 0（例：0123456）。此編碼必須是系統裡已存在的公園，否則該列會被判定為錯誤。
遊戲區代號同一座公園內各遊戲區以 A、B、C… 表示（第 1 區 = A、第 2 區 = B，依此類推）。
日期欄一律用民國年，格式 民國年/月/日（例：民國 113 年 3 月 15 日填 113/03/15）。例如備查日期、檢驗報告日期、稽查日期、各項改善日期。
年 / 月份欄自主檢查、稽查以「年＋月」分開定位：民國年填整數（例：113），月份填 1～12。
是 / 否欄直接填中文「是」或「否」。
附件欄（填檔名）填實體檔案的完整檔名（含副檔名），例：0123456_基本資料.pdf。該檔需確實放在對應模組的附件資料夾內，檔名要完全一致（含大小寫與副檔名）。
標題列 / 空列第 1 列是欄位標題請勿刪除；資料從第 2 列開始。整列空白會被略過。
重複資料若同一筆紀錄已存在於系統，匯入時會自動跳過並提示，不會重複建立。因此檔案可以安心重跑。

✓ 必填 △ 條件必填（視情況，說明欄會註明） 空白 = 選填

三、檔案一：備查

一列 = 一個遊戲區。 同一座公園、同一份備查文號與備查日期的多列，會自動歸成「同一筆備查」。

欄位必填格式 / 說明範例
公園統一編碼✓7 碼0123456
遊戲區代號✓A / B / C…A
遊戲區名稱—選填，無則留空北側沙坑遊戲區
備查文號✓機關核備文號北市建公字第1130001號
備查日期✓民國年/月/日113/03/15
備查類型✓填 新設 或 變更新設
基本資料表檔名✓附件0123456A_基本資料.pdf
廠商保證書檔名✓附件0123456A_保證書.pdf
自主檢查表檔名✓附件0123456A_自主檢查.pdf
平面圖檔名✓附件0123456A_平面圖.pdf
管理人員證書檔名✓附件0123456A_證書.pdf
檢驗報告日期✓民國年/月/日，合格報告的日期113/03/01
檢驗報告檔名✓附件0123456A_檢驗報告.pdf
填寫示意 一座公園有 2 個遊戲區、同一份備查 → 填成 2 列，公園編碼／備查文號／備查日期相同，遊戲區代號分別為 A、B：
公園編碼 遊戲區 備查文號 備查日期 備查類型 … 0123456 A 北市建公字第1130001號 113/03/15 新設 … 0123456 B 北市建公字第1130001號 113/03/15 新設 …
匯入後系統會自動做的事 每筆檢驗報告會自動建立一筆「維護（定檢）待辦」，下次定檢到期日 = 檢驗報告日期 + 3 年。所以你不需要在備查檔裡處理定檢到期。

四、檔案二：維護管理（定檢）

一列 = 一次定檢的最終結果。 同一個遊戲區做過很多次定檢，就填很多列，並請依日期由舊到新由上往下排列。每一列要記錄「這次定檢最後的結果」（合格／待改善／已完成改善）。

關鍵：用「備查日期」把定檢綁到正確的那一輪備查 一個遊戲區可能備查過不只一次（例如後來改建又重新備查）。每一次備查都有自己的一條定檢歷史。
因此維護的每一列，要用 公園編碼 + 遊戲區代號 + 對應備查日期 指出「這筆定檢是接在哪一次備查之後」。請填該輪備查在「備查檔」裡所使用的備查日期。
欄位必填格式 / 說明範例
公園統一編碼✓7 碼（定位用）0123456
遊戲區代號✓A / B / C…（定位用）A
對應備查日期✓民國年/月/日，填該輪備查的備查日期113/03/15
排檢狀態—是 / 否是
檢驗結果✓填 合格 / 待改善 / 已完成改善合格
改善期程分級△「待改善」時必填：L1(10日) / L2(1個月) / L3(3個月)L2
限期改善日期△「待改善」時必填，民國年/月/日113/07/01
實際完成改善日期△「已完成改善」時必填，民國年/月/日113/06/20
維護合格日期△「合格 / 已完成改善」且要成為新定檢基準時填，民國年/月/日113/06/25
維護檢驗報告檔名△附件；有填維護合格日期則必附0123456A_維護報告_113.pdf
缺失項目檔名—附件（如有缺失清單）0123456A_缺失.pdf
備註—選填

每一列依「檢驗結果」要填的欄位

  • 合格：本次定檢通過。若這次有開立新的合格報告（作為下一次定檢的起點），請填維護合格日期並附維護檢驗報告。
  • 待改善：發現缺失、尚未改善完成。必填改善期程分級、限期改善日期、缺失項目檔名。
  • 已完成改善：原本待改善、現已改善完成。必填實際完成改善日期；若改善後複檢合格並開立報告，再填維護合格日期＋維護檢驗報告。
兩個最容易出錯的地方（會導致匯入失敗）
  • 「待改善」後來改善完成，請用「已完成改善」一列表示（同一列同時填限期改善日期與實際完成改善日期），不要拆成「待改善」＋「已完成改善」兩列——拆兩列時第二列會找不到可接續的定檢。
  • 同一輪備查中，「待改善」只能放在最後一列（代表目前仍在改善中）。中間若要接續下一次定檢，該列必須是「合格」或「已完成改善」並填維護合格日期。

定檢的「版本鏈」是怎麼運作的

每當一筆定檢「合格（或已完成改善）且填了維護合格日期」，系統會把它當成新的定檢基準：自動產生一份新報告，並把下次定檢到期日往後算 3 年。你後面更晚的定檢列，就會自動接到這個新基準上。所以只要依日期由舊到新排好，系統會自動把整條歷史串起來。

同一遊戲區備查兩次的填法 假設 A 區民國 109 年備查過一次、民國 113 年又重新備查。兩段定檢歷史用「對應備查日期」區分：
公園編碼 遊戲區 對應備查日期 檢驗結果 維護合格日期 … 0123456 A 109/05/01 合格 109/05/01 ← 屬 109 那輪 0123456 A 109/05/01 待改善 （空） ← 仍屬 109 那輪 0123456 A 113/03/15 合格 113/03/15 ← 屬 113 新一輪
新一輪（113 年）匯入後，系統會自動把舊一輪尚未完成的定檢標記為「已被取代」，只保留最新一輪為進行中。你只要把日期與「對應備查日期」填正確即可，不需手動處理取代。
前提 維護檔要能匯入，前提是該遊戲區的「備查」已經先匯入（或系統本來就有）。請確實遵守匯入順序：先備查、再維護。

六、檔案四：稽查管理

一列 = 某座公園、某年某月的一筆稽查。

欄位必填格式 / 說明範例
公園統一編碼✓7 碼0123456
行政區—可留空，系統會自動帶入中正區
民國年✓整數（民國）113
月份✓1～124
預定稽查日期—民國年/月/日113/04/10
實際稽查日期✓民國年/月/日113/04/12
稽查結果✓填 合格 或 改善中合格
逾期改善日期△「改善中」時必填，民國年/月/日113/05/12
備註—選填
基本資料表檔名△附件；稽查結果為「合格」時必填（改善中可免）0123456_113_04_基本資料.pdf
廠商保證書檔名△附件；合格時必填0123456_113_04_保證書.pdf
管理人員識別證檔名△附件；合格時必填0123456_113_04_識別證.pdf
稽核紀錄檔名△附件；合格時必填0123456_113_04_稽核紀錄.pdf
提醒
  • 稽查只對應到「公園」，不需要填遊戲區代號。
  • 同一座公園、同一年度只會有一筆稽查紀錄（月份代表該年實際稽查的月份）。請勿為同一公園同年度填多列。
  • 稽查結果為「合格」時，4 類文件皆需附上；「改善中」時文件可留空，但逾期改善日期必填。
  • 若某公園當年「改善中」後來已改善完成，仍記為同一列：稽查結果填「合格」並保留逾期改善日期。

七、完成前檢查清單 & 常見錯誤

交付前請逐項確認

  1. 四份 Excel 的第一列標題都沒有被更動或刪除。
  2. 所有公園編碼都是 7 碼、不足補 0，且確實是系統現有的公園。
  3. 所有日期都是民國年格式（例：113/03/15）；年、月分開的欄位也用民國年。
  4. 每個附件欄填的檔名，都能在對應模組的附件資料夾裡找到、且檔名完全一致。
  5. 必填欄（標示 ✓）都有填；條件必填欄（△）依說明補齊。
  6. 維護檔的每一列都填了正確的「對應備查日期」，且同一遊戲區的定檢已依日期由舊到新排序。
  7. 維護檔中「待改善」的列已補齊改善期程分級、限期改善日期、缺失項目檔名，且「待改善」只出現在該輪的最後一列；改善完成的情況用「已完成改善」單列表示。
  8. 稽查檔中同一公園同年度只有一列；「合格」列已附 4 類文件，「改善中」列已填逾期改善日期。
  9. 已依「備查 → 維護 → 自主檢查 → 稽查」的順序整理。

常見錯誤

錯誤情形結果如何修正
公園編碼不存在或位數不對該列匯入失敗確認編碼為 7 碼、補 0，且為系統現有公園
附件欄檔名與資料夾內檔名對不上找不到附件，該列失敗檢查錯字、副檔名、是否漏放檔案
日期寫成西元年（如 2024）或用「-」分隔日期無法判讀一律改成民國年 113/03/15 形式
必填欄留空該列失敗並提示缺哪一欄補齊後重跑該列
維護「對應備查日期」填錯輪次定檢綁到錯誤的備查對照備查檔，填正確那一輪的備查日期
維護「待改善」漏填改善分級／限期改善日期／缺失項目檔名該列失敗三欄皆為待改善必填，請補齊
把「待改善→已完成改善」拆成兩列第二列找不到可接續的定檢而失敗合併為「已完成改善」一列，同列填限期＋實際完成改善日期
稽查同一公園同年度填多列重複、第二列被拒一公園一年度只填一列
先匯入維護、還沒匯入備查維護找不到報告基準務必先完成備查匯入
放心重跑 系統會依邏輯鍵（備查：編碼＋文號；自主檢查／稽查：編碼＋年＋月）判斷重複，已存在的會自動跳過。修正錯誤列後再次匯入，不會造成重複資料。
